# 全社AI利用ガイドライン

製造・技術・生産技術・営業の全部門を対象とした、AI活用の共通指針。`SECURITY_RULES.md` が「絶対に守るべき最低ライン」であるのに対し、本ガイドラインは日々の判断で迷ったときの実務的な目安（SHOULD）を示す。ルールとガイドラインが矛盾する場合はルールを優先する。

## 1. 基本方針

- AIは各部門の判断・専門性を**代替するもの**ではなく**増幅するもの**として導入する。最終判断の責任は常に人（部門の担当者・責任者）が持つ。
- 部門横断で画一的なツール・ルールを押し付けず、部門ごとの業務特性に合わせて適用範囲・運用方法を調整する。

## 2. データ最小化と部門別の機密性

各部門で機密性の高いデータの種類が異なることを認識し、目的から逆算して必要最小限のデータ範囲を用いる。

| 部門 | 特に注意すべきデータ |
|---|---|
| 製造 | 歩留まり、不良率、工程稼働データ |
| 技術 | 図面、設計仕様、特許・知財情報 |
| 生産技術 | 設備仕様、治具・工程原価情報 |
| 営業 | 顧客情報、見積・価格条件、契約内容 |

外部AIサービスに投入する前に、上記データが含まれていないか必ず確認し、必要に応じて匿名化・マスキングする。

## 3. 部門との信頼構築

- 各部門にデータ提供を依頼する際は、「何のために・どこまでの範囲で・誰が見るか」を必ず先に説明する。無断でのデータ収集は行わない。
- 製造: なぜなぜ分析やQCストーリーの記録をAIで解析する場合、個人の失敗を評価・査定に使わないことを明示する。
- 技術: 設計ノウハウ・暗黙知をAIで分析・形式知化する場合、成果物の権利・帰属を明確にし、無断で外部に共有しない。
- 生産技術: 既存の改善サイクル（工程FMEA・標準化活動）とAI活用を二重管理にせず、既存プロセスに組み込む形で提案する。
- 営業: 顧客対応にAIを使う場合、顧客関係を薄めるのではなく、事前準備・情報整理等の**下支え**として位置づけ、最終的な顧客対応は担当者が行うことを原則とする。

## 4. モデル・提案の説明可能性

- 判定・提案の根拠は、可能な限り可視化し、各部門が自部門の業務プロセス（なぜなぜ分析・設計レビュー・工程FMEA・商談プロセス等）に接続して検証できる形で提示する。
- LLMを用いた文書生成・要約（提案書作成支援、QCストーリー作成支援等）は、生成結果に一次情報（元データ・元記録）への参照を残し、後から検証可能にする。

## 5. 段階的導入の目安

- 目安として、PoC（1部門・1業務） → 効果確認・部門ヒアリング → 他部門への横展開検討、の各段階を最短でも1サイクルは経てから次段階に進む。
- 効果確認では、定量指標（精度・時間短縮・工数削減・受注率等）と定性指標（部門の受容度、現場の声）の両方を評価する。
- ある部門で成功したパターンを他部門に展開する際も、業務特性の違いを検証してから適用する（そのまま横流ししない）。

## 6. インシデント時の初動

- データ漏えい・誤送信・意図しない外部送信の疑いが生じた場合は、まず対象データの利用停止・共有停止を行い、直ちに推進リーダーへ報告し `LOGS/` に経緯を記録する。原因究明・恒久対策はその後で行う。
