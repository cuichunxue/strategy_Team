# BPR: 教育プロセスのAs-Is / To-Be

対象ソリューション: `specs/SOL-20260810-01_実践伴走型教育プログラム.md`

## As-Is（現状の教育プロセス＝一般的なAIツール操作研修）

```
[研修企画] → [座学・デモ(汎用例題)] → [終了アンケート] → (現場に戻る、実業務には接続されない)
```

- 題材: 汎用的なサンプルデータ・架空の例題
- 進行: 講師が一方向で教える、社員は聞く
- 成果物: 研修の「理解度」「満足度」のみ。実課題は1件も解決されない
- 恐怖への対応: なし（AIの操作方法は教えても、「専門性が評価されないまま代替される恐怖」には触れない）
- 資産化: なし。研修内容は個人のメモで終わり、組織のナレッジにならない
- 典型的な結果: 「研修は分かったが、自分の仕事にどう使えばいいか分からない」という状態で終わる

## To-Be（Action Learning後の教育プロセス）

```
[実課題の持ち込み] → [キックオフ(潜在ニーズと接続)] → [伴走ワークセッション×2-3回]
   → [その場で共同進行者が専門性を保証] → [ラップアップ・SKILLS登録候補の言語化]
   → [SKILLS/への資産化] → [オンデマンド横展開(他部門)]
```

- 題材: 参加者自身の未解決の実課題・実データ
- 進行: ジョブズが伴走し、各部門の専門性を持つ共同進行者が品質・安全・妥当性を都度保証する（Human-in-the-Loop）
- 成果物: 実課題の解決（またはたたき台完成）＋ 再現可能なロジックの言語化
- 恐怖への対応: 「専門性は代替されず、非付加価値作業だけが減る」ことをその場で体感させることで、`LATENT_NEEDS_DIAGNOSIS.md` で特定した恐怖に直接アプローチする
- 資産化: セッション成果物のうち再現性のあるものを `SKILLS/` に登録し、`SKILLS/README.md` のオンデマンド横展開の仕組みを通じて他部門に届ける
- 典型的な結果: 「自分の課題が実際に解決した」という体験を起点に、自走的なAI活用へつながる

## 変化する役割・責任・承認プロセス

| 役割 | As-Is | To-Be |
|---|---|---|
| 進行役 | 外部・内部の研修講師 | ジョブズ（伴走・facilitation） |
| 専門性の担保 | なし（汎用例題のため専門判断が発生しない） | 各部門の共同進行者が都度確認（Human-in-the-Loop、RULES.md 1.3） |
| 成果物の扱い | 個人のメモ、組織資産にならない | `SKILLS/` 登録候補として組織資産化する経路が必須 |
| 品質保証・安全判断 | 対象外（実業務と接続されないため発生しない） | セッション内では「たたき台」までとし、正式な承認フローは通常業務のプロセスに従う（セッション内で意思決定を完結させない） |
