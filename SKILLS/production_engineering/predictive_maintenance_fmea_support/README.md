# スキルモジュール: 予兆検知・設備FMEA支援（predictive_maintenance_fmea_support）

- **発案部門**: production_engineering
- **ステータス**: 提案（未検証。`02_PROTOTYPES/production_engineering` でのPoCを経て資産化する）
- **由来課題・PoC**: 未登録（`01_DEPARTMENTS/production_engineering` に対象課題が起票され次第、紐付ける）

## 1. 目的・対象業務

設備の稼働データ（振動・温度・電流等のセンサーデータ、稼働ログ）から異常予兆を検知し、工程FMEA（故障モード影響解析）のリスク項目の洗い出し・更新を支援する。設備停止による生産損失の未然防止と、FMEA作成・改訂の属人化解消を目的とする。

## 2. 入力・出力

- 入力: 設備センサーデータ、稼働ログ、既存の工程FMEAシート
- 出力: 異常予兆のアラート候補（確信度付き）、FMEAの故障モード・影響度の見直し候補

## 3. 前提条件・使用データ

- 必要なデータ・システム連携: 設備のセンサーデータ収集基盤、既存FMEAシートの電子化
- データの機密区分（`00_GOVERNANCE/SECURITY_RULES.md` 参照）: 設備仕様・工程原価情報（機密性: 中〜高）

## 4. Human-in-the-Loopチェックポイント（必須）

| ステップ | AIが行うこと | 人間が確認・承認すること |
|---|---|---|
| 異常予兆の検知 | センサーデータから異常予兆の候補とその確信度を提示する | アラートへの対応要否・緊急度の判断は生産技術担当者が行う |
| 設備停止・稼働継続判断 | 判断には関与しない（対象外） | 設備を止めるか稼働を継続するかは、必ず人間が最終判断する（RULES.md 1.2） |
| FMEA更新 | 故障モード・影響度の見直し候補を提示する | FMEAシートへの反映可否は生産技術担当者・レビュー会議で決定する |

## 5. 限界・注意点

- 学習データに含まれない未知の故障モードは検知できない可能性がある。
- 誤検知（過検知・見逃し）のリスクを常に開示し、確信度が低い場合は「参考情報」であることを明示する。
- 検知結果のみをもって設備を自動停止させる運用は導入しない。
