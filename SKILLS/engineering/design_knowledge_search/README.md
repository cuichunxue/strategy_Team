# スキルモジュール: 設計ナレッジ検索（design_knowledge_search）

- **発案部門**: engineering
- **ステータス**: 提案（未検証。`02_PROTOTYPES/engineering` でのPoCを経て資産化する）
- **由来課題・PoC**: 未登録（`01_DEPARTMENTS/engineering` に対象課題が起票され次第、紐付ける）

## 1. 目的・対象業務

過去の設計図面・仕様書・設計レビュー議事録などの設計資産から、類似設計・関連する過去の検討事項（採用しなかった案とその理由を含む）を検索・要約し、新規設計時の調査工数を削減する。技術伝承（暗黙知の形式知化）の入口としても位置づける。

## 2. 入力・出力

- 入力: 設計対象のキーワード・仕様条件、検索対象の設計資産（図面メタデータ、仕様書、設計レビュー議事録）
- 出力: 関連する過去設計・検討事項の候補リストと出典（一次情報への参照）

## 3. 前提条件・使用データ

- 必要なデータ・システム連携: 設計資産の電子化・検索可能な形での蓄積
- データの機密区分（`00_GOVERNANCE/SECURITY_RULES.md` 参照）: 図面・設計仕様・特許等の知的財産（機密性: 高）。外部AIサービスへの投入は原則不可、社内環境での運用を前提とする

## 4. Human-in-the-Loopチェックポイント（必須）

| ステップ | AIが行うこと | 人間が確認・承認すること |
|---|---|---|
| 検索結果の提示 | 関連候補を出典付きで提示する | 技術的な妥当性・適用可否は設計者が判断する |
| 設計判断への反映 | 判断には関与しない（対象外） | 新規設計への採用・不採用の最終判断は設計者・設計レビューが行う |
| 社外共有 | 判断には関与しない（対象外） | 検索結果に含まれる設計資産を社外に共有する場合、知財部門・上長の承認を得る |

## 5. 限界・注意点

- 電子化・構造化されていない過去資産は検索対象にできない。
- 技術的な正しさ・実現可能性の判断は代行しない。あくまで「候補の提示」に留まる。
