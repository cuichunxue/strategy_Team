# スキルモジュール: 信頼性解析モデル（reliability_analysis_model）

- **発祥部門**: production_engineering
- **ステータス**: 提案（未実証。`02_SOLUTIONS/production_engineering` での実証を経て資産化する）
- **由来診断・ソリューション**: 未登録（`01_DIAGNOSTICS/production_engineering` に対象診断が起票され次第、紐付ける）

## 1. 目的・対象業務

設備・部品の稼働データ・故障データから信頼性解析（ワイブル分析等）を行い、故障モードごとの平均故障間隔（MTBF）・故障率の推移を定量化する。生産技術部門の「歩留まりのばらつきは職人の勘の問題」という言い分を、測定可能な条件に還元して検証するための解析モデル。

## 2. 入力・出力

- 入力: 設備・部品の稼働ログ、故障・保全記録
- 出力: 故障モード別の信頼性指標（MTBF、故障率曲線）、予防保全のタイミング提案

## 3. 前提条件・使用データ

- 必要なデータ・システム連携: 稼働ログ・保全記録の電子化と十分なサンプル数
- データの機密区分（RULES.md 5章参照）: 設備仕様・工程原価情報（機密性: 中〜高）

## 4. Human-in-the-Loopチェックポイント（必須）

| ステップ | AIが行うこと | 人間が確認・承認すること |
|---|---|---|
| 信頼性指標の算出 | 稼働・故障データから信頼性指標を算出し提示する | 算出結果の妥当性（サンプル数・前提条件の適切さ）を生産技術担当者が確認する |
| 保全タイミングの提案 | 予防保全の推奨タイミングを提示する | 実際の保全計画への反映は生産技術担当者が判断する |
| 設備停止・稼働継続判断 | 判断には関与しない（対象外） | 設備を止めるか稼働を継続するかは、必ず人間が最終判断する（RULES.md 1.3） |

## 6. 限界・注意点

- サンプル数が少ない設備・部品では信頼区間が広く、解析結果の確度が低下する。
- 「職人の勘」の全てが測定可能な条件に還元できるとは限らない。還元できなかった部分は無理に定量化せず、暗黙知として別途扱う。
