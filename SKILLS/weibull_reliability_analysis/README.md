# スキルモジュール: Weibull分布による設備寿命・予兆検知解析（weibull_reliability_analysis）

- **発祥部門**: production_engineering
- **ステータス**: 提案（未実証。`02_SOLUTIONS/production_engineering` での実証を経て資産化する）
- **由来診断・ソリューション**: `01_DIAGNOSTICS/production_engineering/DIAG-20260810-03_突発停止と保全計画の属人化.md`
- **依存関係（前提スキル）**: なし。ただし `01_DIAGNOSTICS/META_ROOT_CAUSE_SYNTHESIS.md` の分析により、本スキルも「専門判断ロジックの構造化」というメタ真因の生産技術版であり、`qc_story_audit` と統計解析の考え方（工程データに基づくFact-Based判断）を共有する

## 1. 目的・対象業務

設備・部品の稼働データ・故障データにWeibull分布をあてはめ、形状パラメータ（初期故障・偶発故障・摩耗故障のいずれの故障モードか）と尺度パラメータから、故障モードごとの平均故障間隔（MTBF）・故障率の推移・余寿命を定量化する。あわせて稼働データ（振動・温度・電流等のセンサー値）の傾向変化から異常予兆を検知する。生産技術部門の「歩留まりのばらつきは職人の勘の問題」という言い分を、物理的・統計的に測定可能な条件に還元して検証するための解析モデル（RULES.md 2.2 Fact-Basedの実装）。

## 2. 入力・出力

- 入力: 設備・部品の稼働ログ、故障・保全記録、センサーデータ（振動・温度・電流等）
- 出力:
  - Weibull分布のパラメータ（形状パラメータm、尺度パラメータη）と故障モード分類（初期故障/偶発故障/摩耗故障）
  - 故障モード別の信頼性指標（MTBF、故障率曲線、B10寿命等）
  - 異常予兆のアラート候補（確信度付き）と予防保全の推奨タイミング

## 3. 前提条件・使用データ

- 必要なデータ・システム連携: 稼働ログ・保全記録の電子化、Weibull解析に十分なサンプル数（故障件数）、予兆検知用のセンサーデータ収集基盤
- データの機密区分（RULES.md 6章参照）: 設備仕様・工程原価情報（機密性: 中〜高）

## 4. Human-in-the-Loopチェックポイント（必須）

| ステップ | AIが行うこと | 人間が確認・承認すること |
|---|---|---|
| Weibullパラメータ・信頼性指標の算出 | 稼働・故障データからパラメータと信頼性指標を算出し提示する | 算出結果の妥当性（サンプル数・打ち切りデータの扱い・前提条件の適切さ）を生産技術担当者が確認する |
| 異常予兆の検知 | センサーデータから異常予兆の候補とその確信度を提示する | アラートへの対応要否・緊急度の判断は生産技術担当者が行う |
| 保全タイミングの提案 | 予防保全の推奨タイミングを提示する | 実際の保全計画への反映は生産技術担当者が判断する |
| 設備停止・稼働継続判断 | 判断には関与しない（対象外） | 設備を止めるか稼働を継続するかは、必ず人間が最終判断する（RULES.md 1.3） |

## 6. 限界・注意点

- 故障件数（サンプル数）が少ない設備・部品ではWeibullパラメータの信頼区間が広く、解析結果の確度が低下する。
- 「職人の勘」の全てが測定可能な条件に還元できるとは限らない。還元できなかった部分は無理に定量化せず、暗黙知として別途扱う。
- 誤検知（過検知・見逃し）のリスクを常に開示し、確信度が低い場合は「参考情報」であることを明示する。検知結果のみで設備を自動停止させる運用は導入しない。
