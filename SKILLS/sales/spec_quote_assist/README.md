# スキルモジュール: 仕様書・見積補助（spec_quote_assist）

- **発案部門**: sales
- **ステータス**: 提案（未検証。`02_PROTOTYPES/sales` でのPoCを経て資産化する）
- **由来課題・PoC**: 未登録（`01_DEPARTMENTS/sales` に対象課題が起票され次第、紐付ける）

## 1. 目的・対象業務

顧客要求から仕様書・見積書のたたき台を作成し、営業担当者の提案準備にかかる時間を短縮する。過去の類似案件（仕様・価格条件）を参照し、提示までのリードタイムを縮めることで、営業部門が重視する「スピード」に応える。最終的な顧客対応・条件交渉は担当者が行う前提とする。

## 2. 入力・出力

- 入力: 顧客要求事項、過去の類似案件の仕様・見積データ、技術部門・生産技術部門から提供された技術的制約条件
- 出力: 仕様書・見積書のたたき台（ドラフト）、参照した過去案件の一覧

## 3. 前提条件・使用データ

- 必要なデータ・システム連携: 過去の見積・仕様データの蓄積、技術部門・生産技術部門との連携（技術的制約の確認）
- データの機密区分（`00_GOVERNANCE/SECURITY_RULES.md` 参照）: 顧客情報・見積・契約条件（機密性: 高）。外部AIサービスへの投入前に顧客名・個人情報のマスキング必須

## 4. Human-in-the-Loopチェックポイント（必須）

| ステップ | AIが行うこと | 人間が確認・承認すること |
|---|---|---|
| たたき台の作成 | 過去案件を参照して仕様書・見積書のドラフトを作成する | 技術的妥当性（技術・生産技術部門との整合）を営業担当者が確認する |
| 顧客への提示 | 提示には関与しない（対象外） | 見積・仕様書の最終確定と顧客への提示は、必ず営業担当者が行う（RULES.md 1.2） |
| 価格条件の決定 | 過去の類似案件の価格帯を参考情報として提示する | 最終的な価格条件の決定は営業担当者・上長の承認を得る |

## 5. 限界・注意点

- 特殊仕様・新規性の高い案件では過去案件の参照精度が下がる。技術部門・生産技術部門への確認を省略しない。
- ドラフトをそのまま顧客に提示することは想定していない（RULES.md 1.2、営業部門の「顧客関係が薄れる懸念」への配慮）。
