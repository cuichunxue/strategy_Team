# SKILLS

`02_PROTOTYPES/<部門>` での検証を経て「効果確認・歯止め」まで到達した成功パターンを、部門を横断して再利用可能なモジュールとして資産化するディレクトリ。属人化を防ぎ、発案部門から他部門への横展開を可能にすることが目的。

## 構成ルール

`SKILLS/<スキル名>/` 配下に以下を格納する。

- `README.md` — 用途、適用条件、限界・注意点、由来（発案部門・元になった課題ID・PoC）、他部門への適用可能性の評価
- 実装（コード／プロンプト／テンプレート等）

## README.md 記載必須項目（横展開のため）

1. **由来部門**: どの部門の課題から生まれたか
2. **適用条件**: 前提となるデータ・業務プロセス
3. **限界**: 精度の限界、対応できない条件
4. **横展開時の注意**: 他部門に適用する際に、業務特性の違いにより調整が必要な点（そのまま流用しない）

## 命名例

- `qc_story_audit/`（発案: 製造）— QCストーリーの記述をAIが監査し、論理の飛躍や要因解析の浅さを指摘するスキル
- `design_review_assist/`（発案: 技術）— 設計レビュー資料の整合性チェック・過去設計資産の検索支援
- `process_fmea_support/`（発案: 生産技術）— 工程FMEAの記述支援・リスク見落としチェック
- `proposal_draft_assist/`（発案: 営業）— 見積・提案書のたたき台作成支援（最終判断・顧客対応は担当者が実施）

上記はディレクトリ構成の例であり、実際のスキルは各部門での検証結果に基づき随時追加する。
