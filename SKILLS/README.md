# SKILLS

`02_SOLUTIONS/<部門>` での実証を経て定量インパクトが確認された高度な改革フレームワーク・解析手法を、汎用モジュールとして蓄積するディレクトリ。RULES.md 1.4（成功パターンの標準化・横展開）に基づき、1部門の成果を属人化させず、他部門へ横展開できる状態にすることを目的とする。

## 構造

改革フレームワークはどの部門でも再利用されうる汎用資産であるため、部門別ではなく**フレームワーク（手法）単位**でディレクトリを分ける。

```
SKILLS/
  SKILL_TEMPLATE.md                  … スキルモジュールREADMEの共通テンプレート
  qc_story_audit/                    … 統計的品質管理・QCストーリー監査
  weibull_reliability_analysis/      … Weibull分布による設備寿命・予兆検知解析
  design_knowledge_structuring/      … 技術設計ナレッジの構造化
  spec_quote_automation/             … 営業〜技術の仕様選定・見積自動化（部門横断）
  bpr_spec_framework/                … BPR仕様フレームワーク（業務プロセス再設計の共通フォーマット）
```

上記は現時点で登録済みのスキル一覧であり、非網羅的リストである。`02_SOLUTIONS` での実証を経て、統計解析・機械学習モデル・業務プロセス設計等、新たな高度手法が実証され次第、随時追加する。

- 各スキルモジュール（`SKILLS/<フレームワーク名>/`）には、`SKILL_TEMPLATE.md` に準拠した `README.md` と、実装（コード／プロンプト／テンプレート等）を格納する。
- フレームワークが最初に実証された部門は README 内「発祥部門」に記録するが、ディレクトリは部門で分けない。他部門への適用実績は「横展開履歴」に記録する。

- 「依存関係」は `01_DIAGNOSTICS/META_ROOT_CAUSE_SYNTHESIS.md`（RULES.md 2.5 部門横断メタ真因の統合）の分析結果を反映する。依存関係のあるスキルは、実証順序（着手順）にもこの依存を反映する（前提スキルを先に、または同時に実証する）。

## 自動集積のルール（RULES.md 1.4の運用実装）

「実証したら資産化する」を性善説の努力目標にしない。以下を**登録の必須条件**とする。

1. `02_SOLUTIONS/<部門またはプログラム>` での実証（Action Learningセッションでの実課題解決を含む）で定量インパクトが確認された時点で、**7営業日以内**に `SKILLS/<フレームワーク名>/README.md` の起票（ステータス「提案」または「実証中」）を行う。承認・精緻化は後回しでよいが、起票自体を先送りしない（記憶が新しいうちに構造化しないとナレッジは劣化する）。
2. 起票の一次責任者はジョブズとするが、`02_SOLUTIONS/action_learning_program/` のセッションでは、その場に同席する共同進行者（各部門の専門担当者）が「これは他部門にも使えるのでは」と感じた時点でその場で起票候補としてジョブズに指摘してよい（現場発の気づきを起点とすることを妨げない）。
3. 起票基準は「定量インパクトが確認できたか」であり、「完成度が高いか」ではない。粗いままでもステータス「提案」で登録し、横展開時に精緻化する。

## オンデマンド横展開の仕組み（プル型ナレッジデリバリー）

「決まった時期に全部門へ一斉配布する」プッシュ型ではなく、**部門が新たな課題に直面した瞬間に、既存スキルを引き当てて即座に使える**プル型を基本とする。

1. **診断時のスキルカタログ照合を必須化**: `01_DIAGNOSTICS/<部門>` で新規課題が真因特定済みになった時点で、`02_SOLUTIONS` でのソリューション設計に進む前に、ジョブズは必ず本ページの「スキル一覧・ステータス」表（対象ニーズタグ）と照合し、流用・応用できる既存スキルがないか確認する。ゼロから設計するのは、照合の結果一致するスキルがないと判断した場合に限る。
2. **一致した場合の扱い**: 既存スキルをそのまま複製せず、`SKILL_TEMPLATE.md` の「横展開履歴」に適用部門・適用日・調整点を追記する形で1本化する（RULES.md 1.4、部門間の構造的な違いを踏まえた調整を必須とする）。
3. **申請不要の閲覧性**: `SKILLS/` はリポジトリ内で全部門から閲覧可能とし、部門側からジョブズに「こういう課題があるが、近いスキルはあるか」と直接問い合わせることも可能とする（申請書・承認フローを介さない、オンデマンドの情報提供）。
4. **横展開の記録**: 横展開が発生するたびに、当該スキルの「定量インパクト実績」表に適用部門ごとの実績を追記し、`00_STRATEGY/ROI_LEDGER.md` にも横展開分のROIとして加算する。

## 新規スキル登録の手順

1. `02_SOLUTIONS/<部門>` での実証が定量インパクト（RULES.md 1.2）を確認できたら、**自動集積のルール**に従い7営業日以内に `SKILLS/<フレームワーク名>/` を作成する。
2. `SKILL_TEMPLATE.md` をコピーし、`README.md` を作成する。**Human-in-the-Loopチェックポイント**（RULES.md 1.3）と**定量インパクト実績**、**対象ニーズタグ**は必須記入項目。
3. ジョブズは登録時に、他部門への横展開可能性を必ず検討し、改革オーナーに提案する（RULES.md 1.4）。
4. 他部門での適用が決まった場合、当該スキルの README「横展開履歴」に適用部門・適用日・調整点・実績値を追記する（コピーして新ディレクトリを作らない。実体は1本化する）。
5. 上記の一覧表を更新する。
