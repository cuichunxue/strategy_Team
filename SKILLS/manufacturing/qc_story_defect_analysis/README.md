# スキルモジュール: QCストーリー不良解析（qc_story_defect_analysis）

- **発案部門**: manufacturing
- **ステータス**: 提案（未検証。`02_PROTOTYPES/manufacturing` でのPoCを経て資産化する）
- **由来課題・PoC**: 未登録（`01_DEPARTMENTS/manufacturing` に対象課題が起票され次第、紐付ける）

## 1. 目的・対象業務

製造現場で発生した不良の解析を、QCストーリー（現状把握→目標設定→要因解析→対策立案→効果確認→歯止め）の型に沿って支援する。不良現象・発生条件のテキスト記録や検査データから、要因解析（なぜなぜ分析）の切り口の提示、過去の類似不良事例の検索を行い、現場の解析工数を削減しつつ、解析の論理的な飛躍を防ぐ。

## 2. 入力・出力

- 入力: 不良現象の記録（発生日時・工程・現象・検査データ等）、過去の不良解析記録（QCストーリー・なぜなぜ分析シート）
- 出力: 類似事例候補、要因候補のたたき台（あくまで「たたき台」であり結論ではない）、なぜなぜ分析の深掘り不足箇所の指摘

## 3. 前提条件・使用データ

- 必要なデータ・システム連携: 過去の不良解析記録の蓄積（QCストーリーシート等）、検査工程データ
- データの機密区分（`00_GOVERNANCE/SECURITY_RULES.md` 参照）: 歩留まり・不良率等の工程情報（機密性: 中〜高）。外部AIサービス利用時は匿名化・マスキング必須

## 4. Human-in-the-Loopチェックポイント（必須）

| ステップ | AIが行うこと | 人間が確認・承認すること |
|---|---|---|
| 要因候補の提示 | 過去事例・データから要因候補をたたき台として提示する | 提示された要因候補の妥当性を現場担当者が判断し、採否を決める |
| 合否・出荷可否判定 | 判定には関与しない（対象外） | 合否・出荷可否は必ず人間が判定する（AIは判定に使用しない） |
| 歯止め策の確定 | 過去の類似対策事例を参考情報として提示する | 歯止め策の最終決定は現場責任者が行う |

## 5. 限界・注意点

- 過去記録が少ない新規不良モードには対応できない。
- 「たたき台」の提示に留まり、真因の特定・対策の決定を代行しない。
- 個人の失敗評価・査定には使用しない（`00_GOVERNANCE/AI_USAGE_GUIDELINES.md` 3章参照）。
