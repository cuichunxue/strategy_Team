# スキルモジュール: QCストーリー監査（qc_story_audit）

- **発祥部門**: manufacturing
- **ステータス**: 提案（未実証。`02_SOLUTIONS/manufacturing` での実証を経て資産化する）
- **由来診断・ソリューション**: 未登録（`01_DIAGNOSTICS/manufacturing` に対象診断が起票され次第、紐付ける）

## 1. 目的・対象業務

現場が作成したQCストーリー（現状把握→目標設定→要因解析→対策立案→効果確認→歯止め）の記述を監査し、論理の飛躍・要因解析の浅さ（なぜなぜが真因まで到達していない箇所）・定量根拠の欠落を指摘する。マッケンジーの第一原理診断の考え方を、現場のQCストーリー作成支援に転用したフレームワーク。

## 2. 入力・出力

- 入力: QCストーリーシート（現状把握〜歯止めの記述、関連データ）
- 出力: 論理の飛躍・要因解析不足箇所の指摘リスト、定量根拠が欠落している箇所の指摘

## 3. 前提条件・使用データ

- 必要なデータ・システム連携: QCストーリーシートの電子化
- データの機密区分（RULES.md 5章参照）: 歩留まり・不良率等の工程情報（機密性: 中〜高）

## 4. Human-in-the-Loopチェックポイント（必須）

| ステップ | AIが行うこと | 人間が確認・承認すること |
|---|---|---|
| 論理の飛躍・浅さの指摘 | QCストーリー記述の論理構造を分析し、指摘候補を提示する | 指摘の妥当性を現場担当者・品質保証部門が判断する |
| 合否・出荷可否判定 | 判定には関与しない（対象外） | 合否・出荷可否は必ず人間が判定する（RULES.md 1.3） |
| 歯止め策の評価 | 過去の類似歯止め策との比較情報を提示する | 歯止め策の妥当性の最終判断は品質保証部門が行う |

## 6. 限界・注意点

- QCストーリーの「型」に沿った監査であり、型自体が不適切な場合（そもそもQCストーリーで扱うべきでない課題）は検知できない。
- 指摘はあくまで「たたき台」であり、現場の是正判断を代行しない。
