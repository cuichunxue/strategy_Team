# 01_DIAGNOSTICS

各部門（製造/技術/生産技術/営業）の課題を、第一原理思考で診断するディレクトリ。部門から上がった「表面課題」をそのまま `02_SOLUTIONS` に流さず、必ずここで真因と定量インパクトを特定してから次段階に進める（RULES.md 1.1）。

## サブディレクトリ

| ディレクトリ | 部門 |
|---|---|
| `manufacturing/` | 製造 |
| `engineering/` | 技術（開発・設計） |
| `production_engineering/` | 生産技術 |
| `sales/` | 営業 |

各部門ディレクトリの構成は共通:

- `README.md` — 当該部門の業務特性・構造的ボトルネック仮説（`PROFILE.md` の仮説表を初期値とし、診断結果で更新する）
- `DIAGNOSTIC_TEMPLATE.md` — 第一原理診断シートのテンプレート
- `DIAGNOSTICS_LEDGER.md` — 診断一覧台帳

## 運用方法

1. 部門の表面課題・要望が寄せられたら、当該部門ディレクトリの `DIAGNOSTIC_TEMPLATE.md` をコピーし、`DIAG-YYYYMMDD-連番_課題概要.md` の形式でファイルを作成する。
2. マッケンジーが第一原理診断（なぜなぜ5回以上→制約条件の検証→真因特定→定量インパクト試算）を実施する。
3. 当該部門の `DIAGNOSTICS_LEDGER.md` に1行追加し、ステータスを更新していく。試算値は `00_STRATEGY/ROI_LEDGER.md` にも転記する。
4. 真因と定量インパクトが明確になった診断のみ、`02_SOLUTIONS/<部門>` でのソリューション設計に進める。

## ステータス定義

| ステータス | 意味 |
|---|---|
| 起票 | 表面課題が登録されたが未診断 |
| 診断中 | マッケンジーが第一原理診断を実施中 |
| 真因特定済み | 真因・定量インパクト試算が完了し、ソリューション設計に進める状態 |
| ソリューション実証中 | `02_SOLUTIONS/<部門>` で実証中 |
| 資産化 | `SKILLS/` に成功フレームワークとして反映済み |
| 見送り | 定量インパクトが小さい、または制約が真であると判定し着手しない（理由を`LOGS/`に記録） |
| クローズ | 対応完了、または課題自体が解消 |
