# 01_DEPARTMENTS

製造・技術・生産技術・営業、各部門から上がった課題・ニーズを管理するディレクトリ。すべてのAI活用検討は、ここに登録された課題を起点とする（技術起点でシーズを持ち込むことは避ける）。

## サブディレクトリ

| ディレクトリ | 部門 |
|---|---|
| `manufacturing/` | 製造 |
| `engineering/` | 技術（開発・設計） |
| `production_engineering/` | 生産技術 |
| `sales/` | 営業 |

各部門ディレクトリの構成は共通:

- `README.md` — 当該部門の業務特性・想定される抵抗感の整理
- `ISSUE_TEMPLATE.md` — 課題登録テンプレート
- `ISSUES_LEDGER.md` — 課題一覧台帳

## 運用方法

1. 課題が発生したら、当該部門ディレクトリの `ISSUE_TEMPLATE.md` をコピーし、`ISS-YYYYMMDD-連番_課題概要.md` の形式でファイルを作成する。
2. 当該部門の `ISSUES_LEDGER.md` に1行追加し、ステータスを更新していく。
3. カイゼンは定期的に全部門を横断で棚卸しし、優先度・実現性・他部門への横展開余地を評価して推進リーダーに検証提案（`02_PROTOTYPES/<部門>` 着手）を行う。

## ステータス定義

| ステータス | 意味 |
|---|---|
| 起票 | 課題が登録されたが未評価 |
| 評価中 | カイゼンが優先度・実現性を評価中 |
| 検証中 | `02_PROTOTYPES/<部門>` でPoCを実施中 |
| 資産化 | `SKILLS/` に成功パターンとして反映済み |
| 見送り | 現時点では着手しないと判断（理由を`LOGS/`に記録） |
| クローズ | 対応完了、または課題自体が解消 |
