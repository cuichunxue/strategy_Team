# 02_PROTOTYPES

01_ISSUES で優先度が高いと評価された課題について、小規模な仮説検証（PoC）を行う実験場。ここでの検証結果が、SKILLS への資産化判断の根拠となる。

## サブディレクトリ

- `scripts/` — 分析コード（Python等）。1検証テーマにつき1サブフォルダを基本とする。
- `prompts/` — LLM活用時のプロンプト資産（バージョン管理する）。
- `specs/` — ツール仕様書・PoC計画書（対象課題ID、検証方法、評価指標、期間、使用データの範囲を明記）。

## 運用ルール

1. 検証を始める前に `specs/` にPoC計画書を作成し、`01_ISSUES` の対象課題IDと紐付ける。
2. 使用データは `00_GOVERNANCE/SECURITY_RULES.md` に従う（原則サンプル化・匿名化データ）。
3. 検証結果（うまくいった／いかなかった）は、成否に関わらず記録する。失敗もなぜなぜ分析の対象として資産価値がある。
4. QCストーリーの「効果確認・歯止め」まで到達した検証は、`SKILLS/` にモジュール化して移管する。
