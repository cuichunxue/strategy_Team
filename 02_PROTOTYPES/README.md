# 02_PROTOTYPES

`01_DEPARTMENTS/<部門>` で優先度が高いと評価された課題について、部門別に小規模な仮説検証（PoC）を行う実験場。ここでの検証結果が、`SKILLS/` への資産化・他部門への横展開判断の根拠となる。

## サブディレクトリ

| ディレクトリ | 部門 |
|---|---|
| `manufacturing/` | 製造 |
| `engineering/` | 技術（開発・設計） |
| `production_engineering/` | 生産技術 |
| `sales/` | 営業 |

各部門ディレクトリの構成は共通:

- `scripts/` — 分析コード（Python等）。1検証テーマにつき1サブフォルダを基本とする。
- `prompts/` — LLM活用時のプロンプト資産（バージョン管理する）。
- `specs/` — PoC計画書（`POC_SPEC_TEMPLATE.md` を使用）。対象課題ID、検証方法、評価指標、期間、使用データの範囲を明記する。

## 運用ルール

1. 検証を始める前に、当該部門の `specs/` にPoC計画書を作成し、`01_DEPARTMENTS/<部門>` の対象課題IDと紐付ける。
2. 使用データは `00_GOVERNANCE/SECURITY_RULES.md` に従う（原則サンプル化・匿名化データ）。部門ごとに機密性の高いデータの種類が異なる点に注意する。
3. 検証結果（うまくいった／いかなかった）は、成否に関わらず記録する。失敗も部門の改善サイクル（なぜなぜ分析・設計レビュー・工程FMEA等）の対象として資産価値がある。
4. 効果確認・歯止めまで到達した検証は、`SKILLS/` にモジュール化して移管し、他部門への横展開可能性を検討する。
